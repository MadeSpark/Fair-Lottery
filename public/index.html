公平性原理

  1. 创建时锁定密钥承诺：创建抽奖的瞬间，服务器生成一个随机密钥并立刻公开它的哈希值（commitHash）。密钥本身要到开奖那一刻才会公开。这保证组织者不能等看到所有参与者之后，才悄悄换一个"对自己有利"的密钥——因为哈希值早就钉死了，事后换密钥会让哈希对不上。
  2. 哈希链记录参与过程：每个人提交编号后，服务器把编号、加入顺序、加入时间按结构化格式哈希，接到上一个哈希后面，像链条一样一环套一环。谁也不能在中途偷偷插入、删除或修改某个人的记录，否则后面所有的哈希值都会连锁性地对不上。
  3. 报名截止时间不可修改：活动创建时就锁定截止时间，系统在此时间后拒绝新参与者。最终种子不包含“点击开奖”的时间，组织者无法通过反复挑选开奖时刻试算结果。
  4. 开奖时揭示密钥：任何人都可以自己算一遍 SHA256(密钥)，看它是否等于创建时公开的 commitHash，从而确认这个密钥没有被事后调换。
  5. 可选叠加公开随机数信标（drand）：drand 是多家机构联合运营的公开随机数网络，每 30 秒产生一个新随机数，产生之前谁都无法预测。创建时锁定报名截止时间之后的轮次，开奖时必须取到该值才能开奖，这个值不受本系统控制，任何人都能去 drand 官方接口自行核实。
  6. 确定性洗牌：把上面所有公开信息混合成最终种子，用它驱动一个标准的 Fisher-Yates 洗牌算法，取前 N 位。这个过程是完全确定性的——同样的输入必然得到同样的输出。
  7. 任何人都能本地复现：项目提供了一个零依赖的独立脚本 scripts/verify.js，只用 Node.js 内置的 crypto 模块重新实现了一遍算法。下载某场抽奖的公开数据后，运行 node verify.js data.json，如果算出的结果和官方公布的不一致，说明数据被篡改或系统有问题。

推荐保持 drand 选项开启。关闭它后是离线兼容模式：仍然可复现、可验证篡改，但服务器生成的密钥对服务器运营者并不具有不可预测性。

你可以点击"查看/开奖"页面里的"下载验证数据"按钮获取某场抽奖的完整 JSON 数据，然后在自己电脑上运行验证脚本核实。

所有数据通过 API 公开可查，欢迎自行编写程序对接验证。
